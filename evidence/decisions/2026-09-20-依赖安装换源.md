# 2026-09-20 依赖安装换源（本地开发用，勿提交进仓库）

- **状态**：已验证
- **日期**：2026-09-20 · **记录人**：T5 开发者
- **关联**：issue #6 开发过程中发现；影响所有新装环境的组员

## 背景

首次 `uv sync` 在 PyPI 官方源下**安装不动**：耗时 50 分钟仅下载约 50MB，PySide6 全家桶
（essentials + addons ≈ 250MB）按此速度需要 1 小时以上。一度误判为"网速慢"。

## 实测数据（2026-09-20，本项目开发机，Windows 11）

用同一个真实 wheel（`pyside6_essentials-*-win_amd64.whl`）各下 12 秒计时：

| 源 | 实测吞吐 | 备注 |
|---|---|---|
| PyPI 官方（files.pythonhosted.org） | **17.5 KB/s** | 装完需 1h+ |
| 清华 TUNA 镜像 | **10.3 MB/s** | 快约 **600 倍**，整包 28 秒装完 |
| 阿里云镜像 | 不可达 | 未采用 |

## 结论

**本地开发**装依赖时临时指定清华源：

```bash
export UV_DEFAULT_INDEX=https://pypi.tuna.tsinghua.edu.cn/simple
uv sync
git checkout uv.lock     # ★ 关键：还原后再提交
```

**为什么必须还原 `uv.lock`**：换源会让 lock 里每个包的
`source = { registry = "..." }` 与 wheel/sdist 的 `url` 全部改写成镜像地址（实测
79 行 +、79 行 −）。若提交上去：
1. 境外的 CI（GitHub Actions，三平台矩阵）与没配镜像的组员会去拉清华地址，反而变慢或失败；
2. lock 文件的意义是"锁定可复现的依赖来源"，改写来源即破坏可复现性。

**已验证**：还原 lock 后再执行 `uv sync` 耗时 0.07 秒（按 wheel 的 sha256 命中本地
缓存，不触发重新下载），环境照常可用。所以"用镜像装、提交原版 lock"这条路是通的。

## 注意

- **CI 不换源**：GitHub Actions 在境外，官方源本来就快，不要把镜像地址写进
  `.github/workflows/` 或 `pyproject.toml`。
- 本记录只影响本地装包速度，**不改动任何依赖版本**：换源前后 `uv.lock` 中的包版本与
  sha256 完全一致。
