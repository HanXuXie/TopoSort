# 2026-09-20 界面壳（T5）实现决定

- **状态**：已实现，待组长确认其中第 1、7 条
- **日期**：2026-09-20 · **决策人**：T5 开发者（ui）
- **关联**：issue #6（T5）、[2026-09-15-契约定案.md](2026-09-15-契约定案.md)、[2026-09-15-任务拆分总表.md](2026-09-15-任务拆分总表.md)
- **地位**：T5 实现期间做出的取舍记录。凡与契约定案冲突之处，以契约为准并在此登记。

## 背景

T5 要交付「主窗口 + 输入 + 控制条 + 泳道 + 结果流」的界面壳。开工时 T2（算法）、
T3（事件）、T4（渲染）三个模块均未合并，其公共 API 全部抛 `NotImplementedError`；
而 T1 预埋的验收测试 `app/tests/test_ui.py` 中有 3 条端到端用例（粘贴→开始→结果、
两类错误提示）**必须要有 T2 才能真正通过**。以下决定围绕「如何在不阻塞、不造假的
前提下先把壳做完」而做。

## 决定

### 1. 依赖未就绪时的降级策略（待组长确认）

- **选项**：A 等 T2/T3/T4 合并后再开工；B 界面内嵌临时假数据让测试变绿；C 照契约
  调用公共 API，捕获 `NotImplementedError` 后降级提示。
- **结论**：选 C。
- **理由**：B 会在联调时留下必须拆除的假数据，且属虚报进度；C 的同一份代码在模块
  合并后自动转真，零返工。降级时状态行明示「某模块尚未完成」，用户不会被误导。

### 2. 错误呈现方式：状态行横幅，不用模态对话框

- **选项**：A `QMessageBox.exec()` 弹窗；B `QMessageBox.show()` 非模态；C 窗口底部
  状态行横幅 + `error_text()` 读取。
- **结论**：选 C（`error_text()` 语义与契约「对话框或状态栏」一致）。
- **理由**：`exec()` 会阻塞事件循环，pytest 与截图脚本都会卡死；横幅无色差风险、
  可截图、可断言。

### 3. 两类错误的文案格式

- 解析错误：`解析错误：第 N 行解析失败：<原因>（原文：'...'）`——**含行号 N**，
  直接复用 `ParseError.__str__`，不另造格式。
- 环：`检测到环：{A、B} 相互依赖，不存在拓扑序`——**含「环」字**，节点集取自
  `Graph.cycle_nodes()` 排序后拼接。

### 4. 结果流上限 `MAX_ORDERS = 2000`

- **理由**：全序枚举在稠密分叉图上是阶乘级，界面必须设上限防止卡死。2000 远超演示
  所需，且 `iter_topo_orders(max_count=...)` 是契约已有能力。

### 5. 泳道上限取契约值 8、速度滑块单位「每拍毫秒」

- 泳道上限 `LANE_LIMIT = 8` 与契约定案第 4 节一致，超限分支不建行、仅显示溢出计数
  （仍照常计数）。
- 速度滑块 80–1200 ms/拍，默认 400（契约 `tick_ms` 默认值）。**右移 = 更快**，用
  `setInvertedAppearance(True)` 实现，标签实时显示数值避免歧义。

### 6. 截图方式：`tools/shoot.py` + `QWidget.grab()`

- **选项**：A 手动 Win+Shift+S 截屏；B `pyautogui`/`PIL.ImageGrab` 抓屏；C Qt 的
  `grab()` 脚本化。
- **结论**：选 C。
- **理由**：B 需 `uv add` 新依赖（红线：新增依赖须先开 issue）且是平台专属 API；A
  无法保证命名规范与 >20KB 门槛（`tools/check_docs.py` 机械检查），动画/弹窗状态也
  难卡准。`grab()` 是 Qt 自己重绘窗口到 `QPixmap`，三端通用、不受遮挡。
- **附加约定**：脚本对未就绪模块打印「跳过」，**不生成占位假图**。

### 7. 修正 `test_ui.py::TestFileIO::test_save_open_roundtrip`（待组长确认）

- **问题**：原用例未调用 `set_input` 即断言 `save_to → load_from` 往返等于 `CANON`。
  该断言隐含「新建窗口的默认输入必须恰为标准示例图」这一**契约未规定**的行为。
- **结论**：判定为验收测试笔误，在本用例开头补一行 `win.set_input(CANON)`。
- **理由**：改测试等于改验收标准，故「补一行使其符合原意」比「为迁就测试而规定
  默认预填标准示例」更保守。**已在 issue #6 留言报备，待组长确认**；若组长认为应
  改为「默认预填示例」，回退此行并改 `MainWindow.__init__` 即可。

### 8. 已识别的排期冲突（需组长裁决）

T5 的 3 条端到端用例通过 `parse()` 走真实链路，因此 **T5 单独合并时 `test_ui` 无法
全绿**，PR 模板「CI 绿」这一勾在 T2 合并前无法满足。按 CI 两层判定策略（L2 模块
`continue-on-error`）不影响他人，但「对应模块 PR 合并时必须翻绿」这一条需要组长
明确：是接受「T5 先合、T2 落地后自动翻绿」，还是要求 T2 先行。**建议前者**，否则
T5 被动等待会挤压 M1/M2 窗口。

## 影响

- 无新增依赖（`uv.lock` 未变动）。
- 未改动 `app/models`、`app/events`、`app/scene` 任何文件，未触碰契约。
- 唯一改动的测试文件为 `app/tests/test_ui.py`，改动内容为上述第 7 条一行。
