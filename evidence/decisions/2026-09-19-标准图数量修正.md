# 2026-09-19 标准图数量修正（7 条，不是 6 条）

- **状态**：已定稿（本文件取代 `2026-09-15-契约定案.md` §8 中"恰 6 条"的口径；evidence 只进不改，故以新文件修正）

- **提议人**：T2 开发者（Asuka，issue #13）· **复核**：T3 独立穷举验证通过
- **关联**：issue #13、issue #4（T3 验收条款受连带影响）

## 背景

标准图 `<A,C> <A,E> <B,C> <C,D>`（节点 A–E）的合法拓扑序数量，在契约定案、conftest、T3 验收条款中均写为 **6**。issue #13 指出实际为 **7**：清单漏了 `A E B C D`（A 在 C/E 前、B 在 C 前、C 在 D 前，全部满足）。

2026-09-19 复核：`itertools.permutations` 穷举 5!=120 个排列逐条验证约束，得到 7 条：

```
A B C D E / A B C E D / A B E C D / A E B C D
B A C D E / B A C E D / B A E C D
```

## 选项

1. **修正数量为 7**：保留 4 条边不动，补全期望清单。
2. **加边 `<B,E>` 保 6**：改变标准图本身，把 E 钉在 B 后，维持"6"。

## 结论

**选 1：数量修正为 7。** 标准图输入不变（4 条边）。

- `app/tests/conftest.py`：`CANON_ORDERS` 补入 `["A","E","B","C","D"]`（字典序位置：`A B E C D` 之后）；`CANON_COMPLETE_COUNT = 7`。
- T3（issue #4）验收口径连带修正：**"恰好 7 次 Complete"**；Fork 数以 7 条序对应的事件流为准（golden 固化）。

## 理由

- 算法不得故意漏解——枚举必须给出全部合法序，6 是数学错误不是设计选择。
- 改动面最小：只动数量与期望清单，共享输入图不变，T2/T4/T5 既有引用仅需核对该常量。
- 选项 2 要改共享基准图，牵连 conftest、已归档契约、各模块测试与素材，改动面反而更大。
