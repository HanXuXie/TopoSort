# 2026-09-20 CI 的 L2 模块任务在 Linux 上缺 Qt 系统库

- **状态**：已定位、已报给组长，**未自行修改**
- **日期**：2026-09-20 · **发现人**：T5 开发者（ui）
- **关联**：PR #19（T5）、issue #6（T5）、[契约定案](2026-09-15-契约定案.md) 第 9 节（CI 两层判定策略）
- **涉及文件**：`.github/workflows/ci.yml`（未改动）

## 现象

PR #19 的 CI 结果：

```
✅ L1-infra (ubuntu / macos / windows)      ← 三平台全绿
✅ L2-T2 models 红测试（绿=T2验收）
❌ L2-T3 events 红测试（绿=T3验收）
❌ L2-T4 scene  红测试（绿=T4验收）
❌ L2-T5 ui     红测试（绿=T5验收）
```

本地同一提交 `uv run pytest app/tests/ -q` 是 **66 passed**，L1 也全绿 —— 本地与 CI 结论矛盾。

## 定位过程与证据

### 证据一：master 上 T3/T4 的 L2 同样是红的

在 master 最新提交 `989efb5`（T6 演示脚本，**代码已合并**）上查 check-runs：

```
❌ L2-T4 scene    ❌ L2-T5 ui    ❌ L2-T3 events
```

T3、T4 的实现早已合并且可用，其 L2 仍红 → 排除「某模块实现有问题」。

### 证据二：崩在 `pytest_configure`，一个用例都没跑到

抓 L2-T5 的原始 job 日志（GitHub 该接口 302 到签名存储，签名 URL 不接受
`Authorization` 头，须先不跟随重定向、拿到 `Location` 后**不带凭据**再取）：

```
INTERNALERROR>   File ".../pytestqt/plugin.py", line 241, in pytest_configure
INTERNALERROR>     qt_api.set_qt_api(config.getini("qt_api"))
INTERNALERROR>   File ".../pytestqt/qt_compat.py", line 108, in set_qt_api
INTERNALERROR>     self.QtGui = _import_module("QtGui")
INTERNALERROR> ImportError: libEGL.so.1: cannot open shared object file: No such file or directory
```

退出码 **3**（pytest 内部错误），**不是** 1（断言失败）。时间点在 `pytest_configure`，
即 pytest-qt 插件初始化时 import `QtGui` 就失败了，测试收集尚未开始。

### 根因

`ci.yml` 里只有 L1 的 `infra` 任务装了 Qt 系统库：

```yaml
- name: 安装 Qt 系统库（仅 Linux）
  if: runner.os == 'Linux'
  run: sudo apt-get install -y -qq libegl1 libgl1 libxkbcommon0 libdbus-1-3
```

而 L2 的四个任务（`suite-core` / `suite-events` / `suite-scene` / `suite-ui`）
全部跑在 `ubuntu-latest`，**全都没有这一步**。于是凡加载 pytest-qt 的任务必红。
四个 L2 里只有 T2 绿，正因为它是唯一用 `-p no:pytest-qt` 跑的（models 层本就零 Qt）。

## 决定

### 1. 不在本 PR 内修改 `.github/workflows/ci.yml`（已执行）

- **理由**：该文件属 T1/组长的基建（PR 模板第六节写明「组长 T1 已建」）；且「为了让自己的
  PR 变绿而改 CI」在评审上说不清，即便改法正确。已把完整定位发在 PR #19 留言。
- **代价**：T5 的验收条件「L2-T5 翻绿」在本 PR 内暂时无法满足。**如实标注，不伪造**：
  PR 描述的自检清单里「CI 绿」一项保持未勾，并注明原因。

### 2. 建议修法（请组长定夺）

把 `libegl1 libgl1 libxkbcommon0 libdbus-1-3` 的 apt 安装步骤补进 `suite-events`、
`suite-scene`、`suite-ui` 三个任务；或抽成 composite action 共用，避免以后新增 L2 任务时再漏。

### 3. 佐证本地结论，避免被误读为「本地没测就提 PR」（已执行）

PR 留言与描述中同时给出本地证据：`uv run pytest app/tests/ -q` → 66 passed；
`tools/check_docs.py` → 全部通过；L1 三平台绿。

- 修复 CI 后需回到 PR #19 重跑确认 L2-T3/T4/T5 三项是否一并翻绿
  —— 预期 T3、T4 也会同时转绿，可反向验证本诊断成立。
