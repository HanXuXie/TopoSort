# 04 详细设计

## 1. 算法内核

### 1.1 设计目标

算法内核位于 `app/models/`，负责关系文本解析、不可变图模型、环检测、
最长路径分层、全部拓扑序生成和精确计数。该层不依赖 Qt，供事件层和
界面层通过 `app.models` 的公共 API 调用。

实现遵循 Issue #3，并采用以下已归档结论：

- `evidence/decisions/2026-09-15-契约定案.md`
- `evidence/decisions/2026-09-18-CycleError异常契约.md`
- `evidence/decisions/2026-09-18-标准图拓扑序数量修正.md`

### 1.2 类与模块设计

| 模块 | 类型或函数 | 职责 |
|---|---|---|
| `parser.py` | `ParseError` | 保存行号、原文和错误原因 |
| `parser.py` | `parse()` | 解析文本、去重边、拒绝自环并构造图 |
| `graph.py` | `Graph` | 保存不可变节点集和边集，提供公共查询 |
| `graph.py` | `CycleError` | 表示环图无法完成分层 |
| `enumerator.py` | Kahn 分析 | 计算入度、最长路径层号和卡住节点 |
| `enumerator.py` | 显式栈搜索 | 稳定枚举或只计数全部拓扑序 |

`Graph.nodes` 和 `Graph.edges` 使用 `frozenset`。算法运行时使用局部
邻接表、入度表和栈帧，不修改图对象，因此同一个 `Graph` 可被重复播放
并得到确定结果。

### 1.3 输入解析

解析器按物理行处理输入，空白行跳过。全角括号和逗号先规范化，再接受
以下三种形式：

```text
<A,B>
（A，B）
A,B
```

每个非空行必须恰好包含两个非空节点名。重复关系通过集合去重；
`<A,A>` 作为自环在解析阶段拒绝。格式错误抛出 `ParseError`，其中
`lineno` 从 1 开始，`line` 保留原始文本。

### 1.4 Kahn 图分析

预处理阶段由边集构造按节点名排序的邻接表，并计算每个节点的入度。
所有零入度节点构成初始候选集。处理节点 `u` 时，对每条边 `u -> v`
执行：

```text
layer[v] = max(layer[v], layer[u] + 1)
indegree[v] -= 1
```

当 `indegree[v]` 降为零时，`v` 可继续处理。扫描结束后：

- 所有节点均已释放：图无环，层号即从源点出发的最长路径长度。
- 仍有正入度节点：图有环，这些节点构成 `cycle_nodes()` 返回的
  “卡住节点集”，其中可能包含被环阻塞的下游节点。
- `layers()` 遇到卡住节点时抛出公开的 `CycleError(ValueError)`，
  不返回不完整布局。

单次分析的时间复杂度为 `O(V + E)`，空间复杂度为 `O(V + E)`。

### 1.5 全序枚举

枚举算法把 Kahn 算法中“从零入度候选选择一个节点”的动作扩展为搜索树：
每个候选节点对应一条分支。为避免递归深度限制，搜索使用显式栈。

每个栈帧保存当前候选元组、下一个候选下标，以及进入该层时选择的节点。
一次状态转移包括：

1. 按字典序选择一个候选节点并加入当前路径。
2. 降低所有后继节点的入度。
3. 将新释放的节点并入下一层候选集并排序。
4. 路径覆盖全部节点时输出一份列表副本。
5. 分支结束时弹出栈帧，恢复后继入度和路径。

按字典序深度优先展开前缀树，使 `iter_topo_orders()` 的输出顺序稳定。
`max_count` 在达到指定结果数后立即终止搜索。环图最终会在路径未完整时
耗尽候选，因此不产生结果。

设合法拓扑序数量为 `T`。输出本身已有 `Theta(T * V)` 的大小，所以全部
枚举不可能对任意大图保持多项式时间。

### 1.6 仅计数模式

`count_orders()` 复用同一显式栈状态机，但叶节点只将计数器加一，不复制、
保存或返回完整序列。它降低了结果存储开销，但仍需访问搜索树的每个叶子。

精确统计拓扑序等价于统计偏序的线性扩展，一般情形为 `#P-complete`。
因此“极速模式”表示避免构造结果列表，不表示任意 30/60 节点图都能快速
完成。界面层仍需对高分支图提供截断或用户提示。

参考资料：

- A. B. Kahn, *Topological sorting of large networks*,
  DOI: <https://doi.org/10.1145/368996.369025>
- G. Brightwell and P. Winkler, *Counting Linear Extensions is
  #P-Complete*, DOI: <https://doi.org/10.1145/103418.103441>

## 3. 事件引擎（events/）——T3 撰稿（本章定稿稿）

### 3.1 模块定位与文件结构

事件引擎是算法与动画之间的解耦层：把 Kahn 步进过程翻译成六类 StepEvent，
把"逐条演示"调度成"多泳道伪并发播放"。**零 Qt 依赖**，只读
`Graph.nodes / Graph.edges` 两个数据字段，Kahn 步进自研。

| 文件 | 职责 |
|---|---|
| protocol.py | 六类事件 dataclass 唯一定义 + `event_to_dict`（golden 序列化口径） |
| player.py | 步进内核 `_Kernel` / `_Branch` + 公共门面 `TopoPlayer` |
| timeline.py | 调度层 `Timeline`：泳道、拍、暂停/单步/调速 |

### 3.2 核心数据结构

```
_Branch（一条分支 = 一个部分拓扑序的 Kahn 状态快照）
    bid       int             分支标识（Fork 递增分配）
    indeg     dict[str,int]   各节点剩余入度（分支私有副本）
    frontier  set[str]        当前候选（入度已降为 0）
    enqueued  set[str]        本分支已发过 Enqueue 的节点（候选池去重）
    order     list[str]       已消费序列
    bound     str|None        Fork 绑定的首步备选（首步消费后清空）
    pending_visual bool       后台步进过、池尚未对观众补发

_Kernel（显式分支工作队列）
    _branches dict[int,_Branch]  按 branch_id 索引的活跃分支
    _succs    dict[str,list[str]] 邻接表（全分支共享，只读）
    completed list[tuple]        已完成的拓扑序
    _stuck_union set[str]        各分支卡住节点并集（→ CycleFound）
    capped    bool               max_completes 截断触顶
```

### 3.3 步进算法（`step_branch(bid, visual)`，一步 = 拿一个节点）

1. frontier 空：有剩余节点 → `DeadEnd(branch, 剩余全体)`（剩余节点此刻必然
   全部入度≥1，即环或环下游）；无剩余（空图）→ `Complete((), …)`。
2. frontier 非空，事件顺序固定为：
   `Enqueue*(首次进池节点, 字典序) → Consume(选中节点) → Fork*(k-1) → Enqueue*(本步解锁后继, 字典序) → Complete?(若消费完最后节点)`
3. 选中节点：bound 优先（Fork 子分支首步必须吃绑定备选，且**不再分叉**——
   该步全部备选已由亲代延续与兄弟分支覆盖，再分叉会重复枚举）；否则字典序最小。
4. 分叉：候选 k≥2 且非首步绑定 → 消费前快照状态，为其余 k-1 个备选各克隆
   一条新分支（`Fork(原分支, 新id, 原分支所选)`），branch_id 单调递增。

### 3.4 调度层（`Timeline`）

- **逐拍交错**：`iter_events()` = 无限泳道 Timeline 逐 tick 拼接（同一内核
  两种口径，golden 可互验，测试已锁定）。
- **拍首快照**：每拍只推进拍首已活跃的分支（按 branch_id 升序，前台后台
  交错各一步）；本拍新生/晋升的分支下一拍才推进。
- **拍末补位**：拍末把活跃分支按 id 升序取前 `lane_limit` 条入泳道（出生、
  晋升、释放统一按此规则，天然保证泳道分支不降级）；新入道且后台步进过的
  分支补发 Enqueue，拼在本拍事件末尾。
- **后台分支**：`step_branch(bid, visual=False)` 状态照常推进，仅 Complete
  照发；计数与结果不受泳道限制影响。
- **终止**：全部分支终止（或达 max_completes 截断）→ `CycleFound`（若有）
  拼最后一拍末尾，置 `finished`。

### 3.5 状态机（防御式边界，全表有测试覆盖）

| 调用 \ 状态 | running | paused | finished |
|---|---|---|---|
| tick() | 推进一拍 | 返回 [] | 返回 [] |
| step_once() | 自动暂停后走一拍 | 走一拍，保持 paused | 返回 [] |
| pause() | → paused | 幂等 | 幂等 |
| resume() | 幂等 | → running | 幂等 |
| set_speed(ms) | 生效（下限钳制 max(1, ms)） | 生效 | 生效 |

### 3.6 确定性保证

- 一切集合遍历/事件发射一律 `sorted()` 字典序——抵御 `PYTHONHASHSEED`
  跨进程随机化（已在三种种子下与 golden 逐项比对验证）。
- `order` 用 tuple、`stuck_nodes` 用 frozenset（可哈希、可比、内容序稳定）。
- golden 序列化口径唯一：`event_to_dict`（frozenset→升序 list，tuple→list）。

### 3.7 规模防护

`TopoPlayer(graph, max_completes=None)` / `Timeline(..., max_completes=None)`：
累计 Complete 达上限即收工、不再发任何事件。分支数 = 完整序数（每条序对应
一条分支路径），复杂度与回溯枚举同阶；阶乘爆炸用例（T9）依赖本参数截断。

另设**分叉前置保险丝**：Fork 前检查"已完成数 + 活跃分支数 ≥ max_completes
即不再开新分支"。原因：逐拍交错下首条分支需 n 步才产出首个 Complete，宽并
行图（多独立起点）此前分支已按组合数爆炸（实测 30 节点双链 26s 零产出）；
而每条活跃分支至多产出 1 个 Complete，故该上界与 max_completes 语义自洽。
不影响默认路径（cap=None）与既有事件语义，golden 逐字节不变
（设计留档：定案 §9 v4）。

### 4.6 降级设计（依赖模块未就绪时的行为）

> **现状**：T2 / T3 / T4 已于 2026-09-19～20 合并，本节所述分支**当前不会被触发**。
> 保留它们属于防御性设计（见下方"代价与收益"），T6 联调时决定是否清理。

界面层在调用算法/事件/渲染三个模块的**每个调用点**捕获 `NotImplementedError`，
转为状态行提示，界面不崩溃：

| 失败点 | 提示文案 | 界面表现 |
|---|---|---|
| `parse()` | 算法内核（models 模块）尚未完成，无法解析输入 | 输入区保留，结果流空，状态行红字 |
| `iter_topo_orders()` | 算法内核（models 模块）尚未完成，无法枚举拓扑序 | 同上 |
| `Timeline.tick()` | 事件引擎（events 模块）尚未完成，动画已停止（结果流不受影响） | 结果流照常显示，动画停 |
| `GraphBoard(...)` | 图画板：渲染模块（scene 模块）尚未完成 | 画布区显示占位文字 |

> 文案中**刻意不含版本号数字**（如 "T2"）：`test_ui.py` 用 `"2" in error_text()`
> 断言行号，文案里出现数字 2 会让该用例在模块未完成时**假绿**——测试因错误的原因
> 通过比红着更危险。

**代价与收益**：这套 try/except 在三个模块合并后即成为惰性分支，但它换来了"界面壳可
独立开发与验收"，且删除成本极低（每个模块可逐条清理）。

### 4.7 错误呈现设计

契约要求呈现两类错误：解析错误（含行号）与发现环。

- **形式**：底部状态行横幅（错误时红底红字加粗），不使用模态 `QMessageBox`。
- **理由**：`QMessageBox.exec()` 会阻塞事件循环，自动化测试与截图脚本都会卡死；
  横幅同样满足契约"对话框或状态栏"二者之一，且可截图、可断言。
- **文案格式**：
  - 解析错误：`解析错误：第 N 行解析失败：<原因>（原文：'...'）`——直接复用
    `ParseError.__str__`，不另行格式化，保证与算法层报错口径一致。
  - 环：`检测到环：{A、B} 相互依赖，不存在拓扑序`——节点集取自 `Graph.cycle_nodes()`
    排序后拼接，便于回查是哪几个约束互相矛盾。

### 4.8 泳道与结果流的实现要点

- **泳道**（`lanes.py`）：`branch_id → _LaneRow` 字典；每条泳道维护 `consumed` 节点
  列表与 `state`（idle/ready/active/fork/done/stuck），由 `_LaneRow._refresh()` 统一
  渲染，避免状态散落。超过泳道上限（默认 8，取自契约）的分支**不建行**，仅累计计数
  并显示溢出提示——与 T3 时间线契约"溢出分支不展示但 Complete 照发"一致。
- **结果流**（`results.py`）：内部保存 `list[list[str]]`，控件文本由它生成（形如
  `1. A B C D E`）。对外给的是**序列列表**而非控件文本，避免把展示格式混进数据。
  导出为"一行一条序、空格分隔"，与契约一致。
- **结果上限**：`MAX_ORDERS = 2000`。全序枚举在稠密分叉图上呈阶乘增长，界面必须设
  上限防止卡死；上限经 `iter_topo_orders(max_count=...)` 由算法层截断（与 §1.6
  "极速模式"、T3 §3.7 规模防护同一考虑）。

### 4.9 跨平台处理

- 文件读写：`Path.write_text(..., encoding="utf-8", newline="")`、
  `Path.read_text(encoding="utf-8")`。写入端固定不转换换行，读取端走通用换行，
  保证"本程序存的文件往返一致、外部文件也能正确读入"。
- 无平台专属调用；无硬编码路径分隔符。
- 高 DPI：使用 Qt 默认缩放策略，窗口默认 1280×800。
